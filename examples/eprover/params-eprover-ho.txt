# E prover tuning domain -- HO extension of params-eprover.txt.
#
# Superset of the original small domain: every parameter in params-eprover.txt
# is kept (same name, same domain, same default) so a configuration from that
# space still means the same thing here, plus every option `e-nb7`'s own
# strategy line uses that the small domain could not express (HO extension
# rules, lambda handling, more preprocessing/SAT-checking switches), plus the
# heuristic clause-selection slots grow from 4 to 5 (e-nb7 uses 5). The named
# CEF set (`heur1`..`heur5`) and freq set (`freq1`..`freq5`) are e-nb7's own
# 5 CEFs and 3 distinct freqs -- nb7/nb7dd/fifo/nb7ng/refgoals at
# {1,2,6} -- not the full 20-CEF/6-freq
# solverpy_grackle.trainer.eprover.heuristic.HEURISTIC_CEFS space this file
# started from (reduced 2026-09-02, user: the wider space made the domain
# 1.7e23 configurations without buying anything for a run seeded at e-nb7;
# recoverable from git history if a later run wants it back).
#
# Domains and E defaults verified against solverpy_grackle's
# trainer/eprover/{core,ho,ordering,heuristic}.py and cross-checked directly
# against E sources (this repo, checked out at
# /home/yan/repos/cbboyan/eprover): PROVER/e_options.h for every flag's
# ArgType and E-side default, PROVER/eprover.c for the case handlers, and
# CLAUSES/ccl_satinterface.c for the full GroundingStratNames list `satcheck`
# draws from. Two additions beyond what solverpy_grackle's HoDomain offers:
# `neg_ext`/`pos_ext` gained `max` (a third value the E source accepts
# alongside `all`/`off`, PROVER/eprover.c:2010-2045) and `satcheck` gained the
# rest of `GroundingStratNames` beyond `ConjMinMinFreq` -- `NoGrounding` itself
# is left out of the tunable domain since it duplicates this file's own `none`
# sentinel (both mean "no flag, E's own default"); see the eprover_wrapper.py
# README's own warning about exactly this kind of sentinel duplication.
#
# `--delete-bad-limit` is NOT a parameter here: eprover_ho_wrapper.py always
# emits it fixed at 2000000000 (e-nb7's own value; E's own OptArg default is
# 1500000, solverpy_grackle's runner hardcodes 150000000 -- three different
# constants in circulation, so this file picks the one from the one strategy
# actually run on this benchmark rather than inventing a fourth). Per-instance
# tuning of a memory/incompleteness knob like this one is out of scope for a
# runtime-tuned proof-search space.

# Up to 5 clause-selection heuristic slots, each an independent (heurN,
# freqN) pair -- freq tuned separately from which CEF it multiplies, same
# design choice params-eprover.txt's README documents, not solverpy_grackle's
# fixed (freq, CEF) index pairs. Reduced 2026-09-02 (user) from the full
# 20-CEF/6-freq HEURISTIC_CEFS set (see eprover_ho_wrapper.py's git history)
# down to just the 5 CEFs and 3 freqs e-nb7 itself uses -- the wider space
# made this domain's configuration count 1.7e23 without buying anything for
# a run seeded at e-nb7. `heur1..5`'s defaults are e-nb7's own slot order
# (nb7, nb7dd, fifo, nb7ng, refgoals), so `slots: 5` at every heurN/freqN
# default reproduces e-nb7's heuristic exactly (mod the wrapper's own trailing
# completeness term -- see eprover-ho-random.yaml's initial_config comment).
# `slots 0` emits no `-H`/`--define-heuristic` at all, matching
# params-eprover.txt.
